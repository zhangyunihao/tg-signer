# 抽奖 Bot 处理说明

本文档描述自动抽奖引擎（`tg_signer/giveaway_core.py`）对不同抽奖机器人的处理逻辑，
包括所有 bot 共用的通用流程、个别 bot 的专属处理，以及相关配置常量。

## 一、处理流程总览

每条含抽奖链接的消息按以下顺序过滤，任一步骤不通过即跳过（跳过均不打印逐条日志）：

```
消息（频道历史 / 置顶 / 补漏 / 群组扫描）
  │
  ├─ 关键词过滤（「或」匹配，命中任一即通过）
  ├─ 归属地限制过滤（白名单地区）
  ├─ 双向账号过滤（发言数要求 / 口令要求 → 双向账号跳过）
  ├─ 开奖日期过滤（开奖时间早于当前 → 跳过）
  ├─ 历史去重（已参与记录，可按任务开关忽略）
  │
  ├─ 发送 start（bot 链接 / tg://resolve 深链）
  │
  └─ start 后跟进（_click_confirm）
       ├─ bot 回复「已结束」→ 终态，停止一切后续
       ├─ 防脚本验证（按正文顺序点击 emoji 按钮 → 刷新候选）
       ├─ 自动加入（提取 bot 回复 + 原始帖中的频道/群组目标）
       ├─ 口令任务（帖内「发送口令﹝xx﹞」→ 清单定位群组 → 发送口令）
       ├─ 加入要求存在 → 重发 start 完成参与
       └─ 点击确认按钮（立刻参加/确认/参与…）
```

## 二、通用逻辑（所有 Bot 共用）

### 2.1 关键词匹配

- 任务关键词采用**「或」匹配**：消息命中任一关键词即参与
- 默认关键词：`上海, 现金, 红包`（`DEFAULT_KEYWORDS`）
- 群组（GROUP/SUPERGROUP）置顶消息**旁路关键词过滤**；频道置顶与历史消息正常过滤

### 2.2 关键词匹配范围（抽奖说明剔除）

- 匹配时剔除「⚠️ 抽奖说明：」段落（`strip_rules_section`）
- 说明段里的「每日现金红包」等字样不再误触发关键词
- 标题、奖品内容、参与条件等其他段落正常参与匹配
- 归属地检测、发言数/口令检测、开奖日期解析**不受剔除影响**（读全文）

### 2.3 归属地限制过滤

- 识别参与条件中的「🌏 归属地 陕西」「归属地 上海,江苏」等行
- 白名单地区：`ALLOWED_REGIONS = ("上海",)` —— 无限制或包含上海才参与
- 「全国 / 不限 / 所有 / 全部」视为无限制
- 兼容全角冒号、`，,、/|` 等分隔符、行首 emoji 装饰

### 2.4 双向账号过滤

账户卡片上的「双向」开关（默认关闭，持久化于 `webui_accounts.json` 的 `two_way` 字段）。
标记为双向的账号遇到以下两类帖子自动跳过：

| 条件写法 | 检测正则 |
|---|---|
| 发言数要求 | `发言数大于 10 条`、`发言超过/不少于 N 条` 等（`SPEECH_REQUIRE_RE`） |
| 口令要求 | `发送口令﹝xx﹞`、`口令提示`（`PASSWORD_REQUIRE_RE`） |

非双向账号不受影响；双向账号遇两类要求跳过时不打印日志。

非双向账号遇到口令任务会自动完成（见 2.7）；发言数要求无法即时完成
（取决于账号在群内的历史发言数），保持正常参与流程。

### 2.5 开奖日期过滤

- 解析「📅 开奖日期」附近的年月日时分（兼容 `2026年10月20日 17时22分` 等写法）
- 开奖时间早于当前时间 → 静默跳过（`expired`）
- 连续多条「已结束」回复达 `EXPIRED_STOP_STREAK`(5) 时停止本轮扫描该对象

### 2.6 自动加入（激进模式）

从 bot 回复与原始抽奖帖中提取加入目标，来源包括：

1. **t.me 链接**（正文、隐藏链接 TEXT_URL、tg://resolve 深链）
2. **@用户名**（词边界精确匹配，避免误抓）
3. **按钮 URL**（inline button 的 url 属性）
4. **原始帖参与条件**（「加入：xx 频道」式样）——与 bot 回复合并提取

加入前逐项执行：

- `get_chat` 类型预检：个人用户/机器人静默跳过，失效目标提示
- `get_chat_member(target, "me")` 成员检查：已加入跳过
- `join_chat`：`INVITE_REQUEST_SENT`（私有群待审批）计为成功；`FLOOD_WAIT` 触发限流熔断

### 2.7 加入后重参与

- bot 消息中出现过加入要求（链接式或 LotteryBestBot ❌ 清单）时，加入校验完成后**自动重发一次 start** 完成参与
- `BOTS_RESTART_AFTER_JOIN` 强制名单中的 bot 即使无加入要求也重发

**口令任务自动完成**（非双向账号）：

- 原始帖「└ 🔑 发送口令﹝xx﹞」子行归属上方最近的「加入-名称」行（`extract_password_tasks`，支持 ﹝﹞「」『』【】（）括号变体）
- start → 自动加入完成后，按 bot 回复清单「加入-名称」隐藏链接行（❌/✅ 均收集，`extract_join_name_links`）定位口令群组；名称不一致时按包含关系模糊匹配
- 群组未加入时先加入；随后在群内发送口令文本（随机延迟 2~6 秒错峰），重发 start 由 bot 核验
- 每账号×bot×群组只发送一次（进程内去重）；清单定位不到群组时记日志跳过，不中断参与流程

### 2.8 FLOOD_WAIT 熔断与冷却

- 同一账号对同一 bot **连续 3 次**（`MAX_FLOOD_STRIKES`）限流 → 本轮运行熔断该 bot
- 限流失败写入状态文件，**1 小时冷却**（`FLOOD_COOLDOWN`），重启服务不重复触发
- 加入过程遇 `FLOOD_WAIT` 同样暂停自动加入至等待结束

### 2.9 确认按钮点击

start 后轮询 bot 回复（`confirm_wait` 秒），按钮文字包含以下任一关键词即点击：

```
确认 / 参与 / 参加 / 立即 / 领取 / 报名 / 提交 / 抽奖 / 签到
```

（`DEFAULT_CONFIRM_KEYWORDS`，可通过任务配置扩展）

### 2.10 防脚本验证（按顺序点击 emoji）

start 后 bot 回复「🤖 防脚本验证\n请按顺序点击：【🎯、🐻、🐴】\n点错会冷却 30 秒。」
（正文含「防脚本验证 / 按顺序点击」，如 @dbchoujiang123_bot）时自动完成人机校验：

- 从「【…】」解析需按序点击的 emoji 序列（支持 、，, 空格等分隔或无分隔连写）
- 在该消息的内联键盘上按顺序定位对应**回调按钮**，先校验全部按钮齐全，
  再逐个点击（间隔 0.8~1.6 秒模拟人工节奏）
- 解析不出顺序或键盘缺按钮时**不乱点**（点错有冷却惩罚），仅记日志跳过
- 同一条验证消息进程内只点击一次（重发 start 后旧验证消息仍在候选里，
  避免误点过期验证按钮）；候选中存在多条时只点最新一条
- 点击完成后刷新 bot 最新消息，后续正常走加入/确认按钮流程；
  轮询阶段检测到验证消息也会提前结束等待交给验证处理

## 三、@LotteryBestBot 专属处理

该 bot 的抽奖帖与回复有特殊格式，引擎做了针对性适配（常量 `LOTTERYBEST_BOT = "lotterybestbot"`，仅对此 bot 生效）：

### 3.1 帖子特点

原始抽奖帖参与条件**只写频道/群组名称**，不带 t.me 链接与 @用户名：

```
📮 参与条件：
🎫 加入-（某群组A）
🎫 加入-（某群组B）
└  🎟️ 发言数大于 10 条
```

### 3.2 回复「加入清单」解析（核心适配）

start 后不满足条件时，bot 回复「您需加入指定的群组/频道」清单：

```
您需加入指定的群组/频道

🎰 （某频道C）
🎫 加入-（某频道D） ❌
🎫 加入-（某频道E） ✅
🎫 加入-（某频道F） ❌
```

处理规则（`extract_join_status_targets`）：

- 每行「加入-名称」的文字带 **TEXT_URL 隐藏链接**（复制粘贴看不到，消息实体里有）
- **只提取 ❌（未加入）行的链接**；✅（已加入）行跳过
- `└  🎟️ 发言数大于 N 条 ❌` 等激活任务子行也带 ❌ 但不含「加入」，
  **不是未加入频道行**；清单仅含「已加入行 + 发言任务子行」时不会触发
  「清单含未加入(❌)行但未解析到链接」诊断（仅存在真正的「加入-名称 ❌」
  行解析不到链接时才报）
- 公开频道取用户名（如 `@某频道用户名`）；私有邀请链接（`t.me/+hash`）整链保留
- 无链接实体、非 t.me 链接（帖子路径/bot 深链）忽略
- 提取结果与通用提取合并去重后走统一加入流程
- 清单本身算「加入要求」→ 加入后自动重发 start（该 bot 也在强制重参与名单）

### 3.3 强制重参与

`@lotterybestbot` 与 `@realsaberbot` 在 `BOTS_RESTART_AFTER_JOIN` 名单中：
即使回复中没有加入要求，也会在加入校验完成后重发一次 start。

## 四、Bot 终态识别（通用）

bot 回复含「抽奖活动已结束 / 活动已结束 / 抽奖已结束」（`ENDED_REPLY_RE`，
兼容英文如 @Lottery8Bot 的 "The event has ended or does not exist"）时视为终态：

- 立即停止该抽奖的后续跟进：不轮询、不加入、不重发 start、不点按钮
- start 后直接收到终态回复（`_participate` 同步检测）：不记「已参与」、
  归还参与名额，状态文件按 `note="ended"` 持久化，该链接今后不再重试
  （即使开启「忽略历史成功记录」）
- 加入完成后的重发 start 若收到终态回复，同样立即停止
- confirm_wait 轮询期间仅核对**最新一条**消息，会话中历史遗留的旧终态
  回复不会误杀本次参与
- 终态回复按账号×bot 累计（`MAX_ENDED_STRIKES`）：同一 bot 累计 3 次
  （如对每个 start 一律回复已结束的 bot）后本轮运行熔断，后续新链接
  静默跳过

bot 回复「您已成功报名抽奖（未达标β）您还需完成激活任务才能抽奖！」
「您已获得抽奖资格（已达标）」（`SIGNUP_SUCCESS_RE`）＝**报名成功**：

- 点击按钮后的核对按「参与成功」口径记录日志（未达标仅剩发言数这类
  激活任务，系统标记为完成）
- 清单中的「🎟️ 发言数大于 N 条 ❌」子行按上方最近的「(已)加入-名称」
  行归属群组，推送「还需发言 N 条」提醒到消息中心（`speech_required`
  事件 → `webui_speech_alerts.json`）；✅ 已达标行跳过
- 核对时拉取**近期 4 条** bot 回复逐条扫描发言任务，而非只看最新一条：
  目标清单常被其后自己重发的 /start、bot 的其他回复顶到非最新一条，
  只读最新一条会漏提醒（deux 账户「闵行悠悠」漏提醒的真实日志回归）；
  判定参与成功/未生效仍按最新一条，最新为自身发出的消息判未生效

发言数提醒不依赖参与结果：扫描到**原帖**含「发言数大于 N 条」即按
`_emit_source_speech_tasks` 推 `speech_required`（不等参与成功——弹窗
判成功、无确认按钮、已参与过等不读回复清单的路径此前会漏提醒）。
双向账号不建任务（无法在群里发言），同一账号/群组/要求/标题在消息
中心只提醒一次，与报名成功清单的提醒同键去重。

## 五、配置常量速查

| 常量 | 默认值 | 说明 |
|---|---|---|
| `DEFAULT_KEYWORDS` | `("上海", "现金", "红包")` | 新任务默认关键词（或匹配） |
| `DEFAULT_CONFIRM_KEYWORDS` | 确认/参与/参加… | 确认按钮点击关键词 |
| `ALLOWED_REGIONS` | `("上海",)` | 归属地白名单 |
| `BOTS_RESTART_AFTER_JOIN` | `realsaberbot`、`lotterybestbot` | 强制重参与 bot 名单 |
| `LOTTERYBEST_BOT` | `lotterybestbot` | ❌/✅ 清单解析仅对此 bot 生效 |
| `MAX_FLOOD_STRIKES` | `3` | 同账号同 bot 连续限流熔断阈值 |
| `MAX_ENDED_STRIKES` | `3` | 同账号同 bot 累计「已结束」回复熔断阈值 |
| `FLOOD_COOLDOWN` | `3600` 秒 | 限流失败冷却期 |
| `EXPIRED_STOP_STREAK` | `5` | 连续「已结束」回复后停止扫描 |
| `RESCUE_INTERVAL` | `600` 秒 | 补漏扫描间隔（WebUI 可配，0=关闭） |
| `RESCUE_LIMIT` | `10` 条 | 每次补漏每频道重拉消息数 |
| `SEEN_CAP_PER_CHAT` | `500` 条 | 每频道已处理消息水位线上限 |

## 六、日志说明

**会打印**：`命中 N 个抽奖链接`、`[已参与] 账号 -> bot（来自 频道：标题）`、
加入成功/失败、已提交加入申请、限流熔断、重发 start、确认按钮点击、
已达参与上限（每账号一次）、口令群定位/发送口令/发送失败。

**不打印（静默跳过）**：关键词未命中、归属地限制、双向账号发言数/口令要求、
已开奖、群组置顶水位线重复。
